CLI Commands

This file is the quick command reference for database_system_cli.

Two Equivalent Ingest Entry Points

For a human-operated, bilingual arrow-key workflow:

poetry run j21 menu

For scripts, AI tools, reproducible notes, and automation:

poetry run j21 ingest --help

Both routes call the same fdp.get_data Jobs. The menu does not start a shell subprocess. Before execution it shows the resolved parameters, their sources, target tables, API/storage estimate, Job module, and an equivalent CLI command. Confirmation defaults to No.

All migrated ingest commands support --output text|json. JSON mode emits one versioned JobResult on stdout and sends progress events to stderr:

poetry run j21 ingest daily --market US --date 2026-07-07 --output json

Instrument Master

Refresh active instruments and identifier history:

poetry run j21 ingest instruments --market US

The command uses EODHD symbol-change history before the current exchange list. It writes canonical instruments and identifier history; it does not guess rename relationships.

Historical Stock, ETF, And Fund EOD

Load a small explicit symbol set:

poetry run j21 ingest history \
  --symbols AAPL,MSFT,SPY \
  --asset-types stock,etf,fund \
  --from 2024-01-01 \
  --to 2024-01-31 \
  --instrument-status active

--symbols accepts canonical symbols such as AAPL and provider symbols such as AAPL.US; lookup is performed through the instrument master. Use --instrument-status inactive to fetch only inactive/delisted symbols, or all for both. Empty symbols are rejected because full-universe history should use Bulk EOD.

Each symbol is committed independently under one aggregate task run. An isolated 404/no-data symbol is recorded and the batch continues. Authentication, entitlement, database, or repeated global transient failures stop later symbols.

One-Day Bulk EOD

poetry run j21 ingest daily \
  --market US \
  --date 2026-07-07 \
  --asset-types stock,etf,fund \
  --instrument-status active

Matched rows enter the canonical split price tables. Unmatched provider rows are retained in system.bulk_unmatched_daily_price_observation for later classification and routing.

Daily Range Bulk EOD

Estimate a date range before writing:

poetry run j21 ingest daily-range --from 2024-01-01 --to 2024-01-31 --dry-run

Execute after reviewing the estimate:

poetry run j21 ingest daily-range \
  --from 2024-01-01 \
  --to 2024-01-31 \
  --asset-types stock,etf,fund \
  --instrument-status all \
  --execute \
  --yes \
  --parallel \
  --workers 4

Large API-consuming daily-range --execute --yes runs default to user-operated CLI execution. Codex/AI should prepare the command and then verify database state after the user runs it.

Relevant controls:

  • --parallel/--sequential: enable or disable bounded per-day parallel ingestion.
  • --workers: worker count when parallel mode is enabled.
  • --max-requests-per-minute: request-rate throttle; must be at or below EODHD's 1000 requests/minute ceiling.
  • --instrument-status active|all: daily update uses active; historical survivorship-aware matching uses all.
  • --max-api-calls: weighted hard budget charged before every HTTP attempt, including retries.
  • --max-estimated-gb: storage estimate guard.

Runtime defaults live in config/default.yaml and can be overridden with:

  • EODHD_MAX_RETRIES
  • EODHD_RETRY_DELAY_SECONDS
  • EODHD_MAX_REQUESTS_PER_MINUTE
  • EODHD_DAILY_CALL_BUDGET
  • EODHD_DAILY_RANGE_PARALLEL
  • EODHD_DAILY_RANGE_MAX_WORKERS

Delisted Instruments

Load EODHD inactive/delisted stock+ETF+Fund universe:

poetry run j21 ingest delisted-instruments --market US

This writes inactive instruments to us_share.instrument and records delisting facts in us_share.instrument_lifecycle_event. It is idempotent and does not backfill all delisted historical prices by default. The current EODHD delisted symbol list does not return a delisting date, so instrument.delisted_date can remain NULL until another source supplies that date.

Run a small inactive-symbol historical price smoke test only when explicitly needed:

poetry run j21 ingest history \
  --market US \
  --symbols TWTR.US \
  --from 2022-10-20 \
  --to 2022-10-28 \
  --instrument-status inactive

Compatibility note: --include-inactive is still accepted and means --instrument-status all. Use inactive when you only want delisted/inactive symbols and want to avoid spending API calls on active instruments.

Bulk Unmatched Workflow

j21 ingest daily and j21 ingest daily-range first write matched stock/ETF/Fund rows into split daily price tables. Bulk EOD rows that cannot match the current instrument universe are stored in system.bulk_unmatched_daily_price_observation instead of being discarded.

Inspect unmatched rows:

poetry run j21 research bulk-unmatched summary --from 2024-01-01 --to 2024-01-31
poetry run j21 research bulk-unmatched list --from 2024-01-01 --to 2024-01-31 --status unresolved

Classify unresolved rows with strict provider-symbol matching:

poetry run j21 research bulk-unmatched classify --from 2024-01-01 --to 2024-01-31

Preview routeable high-confidence rows:

poetry run j21 ingest bulk-unmatched-route --from 2024-01-01 --to 2024-01-31 --dry-run

Execute only after reviewing the preview:

poetry run j21 ingest bulk-unmatched-route --from 2024-01-01 --to 2024-01-31 --execute --yes

Routing only writes rows that strictly matched an existing stock/ETF/Fund/index instrument_id. Preferred, notes, bonds, warrants, and unknown rows remain in staging.

Historical Bulk identity order is source-date identifier history, current provider symbol, optional EODHD Type compatibility, then exact instrument. Old/current aliases for one natural key are not resolved by response order: the unique dated alias wins and the lower-priority row remains staged as shadowed.

Daily-Price Asset-Type Reconcile

Metadata can correct an instrument type after older prices were written. Plan first:

poetry run j21 migrate daily-price-asset-types --phase plan

After pausing ingest and reviewing every source/target group, execute in bounded transactions:

poetry run j21 migrate daily-price-asset-types --phase execute --chunk-size 1000 --execute --yes

Each chunk copies to the current canonical type table, verifies all OHLCV/source fields, and only then deletes the old-table row. Existing conflicting target payloads stop and roll back the chunk. Rerunning is safe because committed rows no longer appear in the mismatch plan.

ETF/Fund Physical Split

The large-table migration is operator-controlled and resumable:

poetry run j21 migrate fund-daily-price --phase plan
poetry run j21 migrate fund-daily-price --phase copy --backup-file /absolute/backup.sql.gz --execute --yes
poetry run j21 migrate fund-daily-price --phase verify --run-id 1
poetry run j21 migrate fund-daily-price --phase finalize --run-id 1 --execute --yes

copy can resume by run ID. finalize refuses to run unless the current verification proves row conservation, zero natural-key duplicates, zero cross-type rows, and sample checksum match. Do not run OPTIMIZE TABLE as part of this workflow.

Validate, Repair, And Quarantine

poetry run j21 validate daily-price --from 2024-01-01 --to 2024-01-31 --asset-types stock,etf,fund,index
poetry run j21 repair plan-daily-price --from 2024-01-01 --to 2024-01-31
poetry run j21 repair list --status pending_confirmation
poetry run j21 repair confirm --plan-id 123 --yes
poetry run j21 repair run --plan-id 123 --yes
poetry run j21 quarantine plan-daily-price --from 2024-01-01 --to 2024-01-31 --issue-types invalid_ohlcv,price_on_non_trading_day
poetry run j21 quarantine list --status pending_confirmation
poetry run j21 quarantine confirm --plan-id 123 --yes
poetry run j21 quarantine run --plan-id 123 --yes
poetry run j21 validate docs-staleness --root ..

Quarantine archives the full source payload and hash before deleting a canonical row. Planning, confirmation, and execution are separate on purpose. docs-staleness checks that this tutorial covers every current Typer leaf command and that managed Markdown/HTML pairs are synchronized.

Research And Technical Parity

Read local prices:

poetry run j21 research daily-prices \
  --symbols AAPL.US \
  --asset-type stock \
  --from 2024-01-01 \
  --to 2024-03-31 \
  --adjusted

Run the fixed local-vs-EODHD SMA20/EMA20/RSI14 sample. It never permits more than 200 weighted units and does not write the database:

poetry run j21 research technical-validate \
  --symbols AAPL.US,META.US,SPY.US \
  --from 2024-01-01 \
  --to 2024-03-31 \
  --max-api-units 200
