J21 System Schema Table Guide

system schema 保存运行审计、数据质量、人工修复和 reconciliation 状态。它不保存 canonical market data；正式 instrument 和价格仍位于 us_share。本页描述当前代码实际 管理的表，不代表可以绕过 CLI 直接修改。

保留原则

  • 当前版本不自动清理、归档或压缩任何 system 表。
  • run_id、check_run_id、plan ID 和 observation ID 是审计链的一部分，不能按单表随意删除。
  • resolved、routed、shadowed 和 superseded 表示状态已变化，不表示记录可以删除。
  • 若未来需要归档，必须先定义跨表引用、恢复方式和可复算范围，并单独实现迁移任务。

Guided Reconcile 关系

flowchart LR Raw["bulk_unmatched observation"] --> Classify["checkpointed classifier"] Classify --> Run["ingestion_task_run checkpoint"] Classify --> Route["complete-group router"] Route --> Audit["identity resolution audit"] Route --> Price["us_share canonical prices"] Route --> Issue["data quality issue"] Issue --> Check["data quality check run"]

classify 和 route 不调用 EODHD。每个已提交批次的数据修改与 checkpoint 使用同一 transaction；失败批次整体回滚，先前批次保留。身份冲突继续留在 staging，并写入现有质量 表，不自动移动或覆盖 canonical 数据。

运维查询

只读查看运行状态：

poetry run j21 reconcile bulk-unmatched status --run-id <RUN_ID>

查看某一日期范围的 staging 组成：

poetry run j21 reconcile bulk-unmatched summary \
  --from <FROM> --to <TO>

需要清理或归档时，不应直接执行 DELETE。先创建独立任务，评估外键、恢复需求、历史研究 可复算性和磁盘回收成本。
