J21 Terminal Menu

j21 menu 是给人操作的数据拉取入口；j21 ingest 是给 AI、脚本和熟悉命令行的用户使用的确定性入口。两者调用同一组 fdp.get_data Jobs，因此参数校验、API 调用、写库和失败处理不会出现两套口径。

启动

cd database_system_cli
poetry install
poetry run j21 menu

菜单需要真实交互式 terminal。管道、CI 或 agent automation 应改用：

poetry run j21 ingest --help

操作流程

选择语言
-> 选择数据任务
-> 填必需参数
-> 可选高级参数
-> 查看 preflight
-> 查看等价 CLI
-> 人工确认
-> tqdm 进度
-> 结果摘要

Bulk daily / daily-range 成功后会继续进入 Guided Reconcile：

Bulk完成
-> 彩色 staging 统计
-> 10秒核对，可按Enter跳过
-> 确认classify，默认No
-> J21短Logo
-> Rich Live真实批次进度
-> route dry-run
-> 确认route，默认No
-> 分批route
-> 自动daily-price质量检查
-> 最终报告和问题样例

统计、classify、route 和 status 只读取/修改本地 MySQL，EODHD API cost 固定为 0。 两次写操作确认都默认 No；取消不会丢掉已经提交的 Bulk 数据或 reconcile checkpoint。

确认默认是 No。在确认之前，Job 只读取本地配置和数据库做 preflight，不读取 API key、不调用 EODHD、不写业务表。

Preflight 会显示：

  • Job module
  • target tables
  • resolved parameters
  • 每个参数来自 menu 还是 Python Job default
  • work units
  • estimated API calls / rows / storage
  • missing symbols 和 warnings
  • equivalent CLI command

当前菜单任务

Instrument master：

  • active instruments + symbol-change history
  • delisted/inactive instruments

Historical EOD：

  • stock daily
  • ETF daily
  • Fund daily
  • benchmark index daily

Corporate actions：

  • dividend history
  • split history

Bulk EOD：

  • one trading day
  • guarded date range

Reference / reconcile：

  • US market calendar
  • Security ID Mapping：US exchange full sync 或少量 provider symbols
  • Bulk unmatched guided workflow：新建或按 run_id 继续

Validate、repair、quarantine 和普通 research 查询暂时保留为 CLI-only；它们不会在菜单中显示成不可用按钮。

Security ID Mapping

菜单里的 ID Mapping wizard 提供两个互斥 scope：

  • US exchange：按 page[limit] / page[offset] 分页同步全市场。
  • Provider symbols：只查询 AAPL.US,MSFT.US 这类少量明确标的。

高级参数可设置 page size、resume offset、hard API-call budget 和每分钟请求上限。 确认页会显示等价的 j21 ingest id-mappings 命令。预算耗尽时已提交 page 保留，结果中的 next_offset 用于续跑。返回数据没有有效期，因此是 undated crosswalk aliases，不是 current-only 或 PIT history；同一 instrument/type 的多个 validated values 会全部保留。 若分页已完成但仍有 unmatched/invalid 行，结果为 partial_failed 且 next_offset 为空； 这表示后续需要 reconcile，不需要重复拉取整套分页。

Dividends And Splits

Corporate Actions wizard 可以选择：

  • 全部本地 stock scope，或少量明确 stock symbols/provider symbols。
  • dividend、split，或两者。
  • active、inactive/delisted、all。
  • 可选 action date range；留空表示供应商可返回的最大历史。

该 workflow 的 asset type 固定为 stock，Menu 不提供 ETF/Fund 选择，也不会向它们发出 dividend/split 请求。

高级参数包含 instrument limit、并发、workers、checkpoint batch size、每分钟请求上限和 hard API-call budget。该预算包含 User API preflight 和重试；确认页显示真正的总预计成本， 默认仍为取消。每个 instrument 独立提交，坏 provider row 进入 data quality issue，批次完成 后保存 checkpoint。Menu 与 j21 ingest corporate-actions 调用同一个 Job。

Bulk Unmatched Guided Reconcile

菜单默认处理 unresolved + needs_instrument + unknown。ambiguous 和 non_price_asset 只有在高级选项中主动勾选后才会重新分类。超过 100,000 行时 preflight 会醒目警告，但确认一次后可以按 checkpoint 持续跑完，不需要每批确认。

Classifier 默认每批 5,000 observations；router 默认每批 1,000 个完整 (instrument_id, trade_date) 组合。每批数据修改和 checkpoint 在同一 transaction 提交。 按 Ctrl+C 或遇到失败时，本批回滚、先前批次保留；下一次进入 Reference / reconcile， 选择 Resume 并输入 run_id 即可从最后安全位置继续。

Route preview 不写数据。执行 route 后，Menu 自动运行现有 daily-price checks，最终显示：

  • routed / shadowed / route_failed 计数
  • identity audit 和 quality issue 计数
  • checkpoint phase
  • 剩余 unresolved/ambiguous/needs_instrument/unknown 样例

全量 backlog 仍由用户本人在 Menu 中确认启动。小规模 smoke、dry-run 和只读验库可由 agent 执行。

Symbol 和日期规则

Stock/ETF history 同时接受 canonical symbol 和 provider symbol：

AAPL
AAPL.US

两者都通过 us_share.instrument 解析，不会直接给输入盲目追加 .US。未知 symbol 会进入该次 Job 的结构化 failure 结果，不会写入 Bulk unmatched staging。

Stock/ETF history 的 symbol list 不能为空。要做全市场、长日期范围回填，应使用 Bulk daily / daily-range，避免按数万个 symbol 消耗 API calls。

Bulk Menu 的 lifecycle 默认值按场景区分：

  • 不填日期的最新单日 daily：active。
  • 显式历史日期的 daily：all，即 active + inactive。
  • daily-range：all。

这里的 instrument_status 是本地 instrument 匹配范围，不是 EODHD Bulk response 的字段。

参数优先级：

menu/CLI explicit value > Python Job module default > ValueError

Python 默认值位于对应的人类可管理模块，例如：

src/fdp/get_data/historical/get_stk_daily.py
src/fdp/get_data/historical/get_etf_daily.py
src/fdp/get_data/historical/get_index_daily.py

进度与失败

普通 ingest 菜单使用 tqdm 动态进度条；Guided Reconcile 使用 Rich Live 显示真实 批次、速度、ETA、checkpoint 和计数。普通 CLI 使用稳定的逐行 progress event，便于日志 和 AI 读取。Rich reporter 在非 TTY 环境自动退回普通文本，不输出动画控制字符。

Historical history 的每个 symbol 使用独立 transaction，但共享一个 aggregate ingestion_task_run：

  • 已完成 symbol 不会因后续 symbol 失败而回滚。
  • 单个 404/no-data 会记录后继续。
  • 401/402/403 会立即停止。
  • 数据库/解析异常会停止并正确关闭父 run。
  • 连续全局 transient failures 达到阈值后停止未执行 work units。
  • Ctrl+C 保留已提交 symbol，并把 run 标记为 cancelled/partial failure。

给 AI 和脚本的 JSON

需要稳定机器输出时使用：

poetry run j21 ingest daily \
  --market US \
  --date 2026-07-07 \
  --output json

stdout 只输出一个带 schema_version 的 JobResult JSON。运行进度写 stderr；API key 不会进入命令预览、进度或 JSON。

大规模拉数

菜单只是让操作更直观，不会绕过 API-call/storage guard。大规模 daily-range 应由用户本人确认并执行；先审阅 preflight 中的日期、交易日数、API-call cost、estimated rows/GB 和 target tables，再开始写库。
