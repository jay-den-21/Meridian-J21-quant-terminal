J21 Database System CLI Architecture

本文先用五个一级板块解释 database_system_cli，再追踪当前可执行代码。它回答三个问题：

  1. 用户从哪里进入系统？
  2. 数据经过哪些 class/function 才进入数据库？
  3. 修改某一层时，必须联查哪些上下游？

文档会明确区分 Current / 当前实现 与 Target / 目标结构，不把计划写成已经完成。 Markdown 是源文件；同目录 architecture.html 是带可视化图的人类阅读版。

关键边界：CLI、Menu、Python、Skill/MCP 都只是入口 adapter；参数、预算、续跑、 失败策略和结果必须收敛在同一个 fdp.get_data Job 中。数据源网络请求不能占用长事务； 一个 work unit 的正式数据、待处理行、审计和 checkpoint 才在短事务内一起提交。

人类界面统一使用：raw / 原始、pending / 待处理、published / 正式数据、 held / 暂缓处理、quarantined / 已隔离。数据库和旧兼容接口中的 canonical 名称暂不 大规模重命名，避免把文案简化变成高风险 migration。

3. 当前组件流

4. 四种入口如何汇合

4.1 Typer CLI

pyproject.toml 同时把 j21 和兼容命令 fdp 映射到 fdp.cli:app。

poetry run j21 ingest daily ...
-> fdp.cli.ingest_daily()
-> BulkDailyJob.run(override_source="cli")

CLI 负责把字符串转成 date/list/enum，选择 Job，渲染 JobResult。--output json 时，stdout 只输出一个 JSON result，progress 走 stderr。

4.2 Terminal menu

poetry run j21 menu
-> fdp.cli.terminal_menu()
-> fdp.menu.run_terminal_menu()
-> INGEST_JOB_DEFINITIONS + JOB_HANDLERS
-> Job.preflight()
-> 人工确认（默认取消）
-> Job.run(TqdmProgressReporter)

菜单不 shell 调 CLI。它直接调用与 CLI 相同的 Job，因此默认值、预算和失败语义只有 一份。

4.3 Python caller

研究脚本或未来 automation 可以直接实例化 Job：

job = StockDailyJob()
preflight = job.preflight(...)
result = job.run(...)

参数优先级固定为：

CLI/menu/Python explicit value -> Job module default -> ValueError

4.4 Skill 与 MCP

.agents/skills/j21-daily-ingest/ 是操作说明，不复制业务代码。j21-mcp 以 stdio 启动 fdp.mcp.server，并把 daily_preflight、daily_range_preflight、task_list、 task_status、daily_execute 和 daily_range_execute 映射回相同的 Job/TaskLedger。

MCP 默认只读。执行工具必须同时满足服务端 J21_MCP_ENABLE_WRITES=1 和单次调用 confirm_execute=true；它仍受 Daily task fingerprint、live lease、max_api_calls、 自动续跑和质量流程约束。stdio stdout 只用于 MCP protocol，不能混入日志或进度文本。

5. Shared Job 内部流程

fdp.get_data 的四个基础文件：

  • contracts.py：JobPreflight、JobResult、ProgressEvent。
  • runtime.py：创建 SQLAlchemy engine，并延迟创建 EODHD client。
  • registry.py：菜单可发现 Job 的显式清单。
  • reporting.py：跨入口的结果/事件格式辅助。
sequenceDiagram participant U as CLI/Menu/Python participant J as fdp.get_data Job participant DB as MySQL participant R as JobRuntime participant E as EODHD participant I as provider ingest U->>J: explicit parameters opt Job needs database estimates or identity resolution J->>DB: read-only preflight queries end J-->>U: target tables, units, API/storage estimate U->>J: confirmed run J->>R: lazy client construction R-->>J: configured EodhdClient J->>I: run one work unit I->>E: authenticated request with limiter/retry E-->>I: normalized API response I->>DB: validated upsert + audit rows I-->>J: provider load result J-->>U: progress events + versioned JobResult

预算拒绝、dry-run 和菜单取消必须发生在 JobRuntime.client() 之前，因此这些路径不会 读取 API key，也不会消耗 API call。

6. Instrument Master 与生命周期

6.1 Active instruments + symbol history

j21 ingest instruments
-> ActiveInstrumentsJob.run()
-> load_exchange_symbols()
-> EodhdClient.get_symbol_change_history()
-> reconcile_symbol_changes()
-> instrument_identifier_history upsert
-> EodhdClient.get_exchange_symbols()
-> parse_exchange_symbol_rows()
-> instrument upsert
-> ingestion_task_run + api_call_log

身份规则：instrument_id 稳定；instrument.symbol/provider_symbol 保存当前值；旧值和 有效期写入 instrument_identifier_history。不能仅凭 name/ticker 猜测合并。

6.2 Delisted instruments

j21 ingest delisted-instruments
-> DelistedInstrumentsJob.run()
-> load_delisted_instruments()
-> EODHD delisted symbol list
-> parse inactive stock/ETF/Fund rows into canonical asset_type
-> instrument upsert with is_active=false/delisted_date
-> instrument_lifecycle_event upsert by event_key

重跑必须幂等：可以刷新 instrument 当前状态，不可重复制造相同 lifecycle event。

6.3 Security ID Mapping

j21 ingest id-mappings --exchange US|--symbols AAPL.US,...
-> IdentifierMappingJob.preflight()
-> audited EODHD User API allowance check
-> EodhdClient.get_id_mappings()
-> parse/check CUSIP, ISIN, FIGI, LEI, CIK
-> exact current provider_symbol
-> unique historical provider_symbol owner
   -> matched/valid: instrument_identifier_history upsert
   -> unresolved/ambiguous/invalid: system identifier_mapping_unmatched_observation
-> ingestion_task_run + api_call_log + optional next_offset

CLI、菜单和 Python caller 共用同一个 IdentifierMappingJob。exchange mode 使用最多 1000 rows/page 的 offset pagination；targeted symbols 只用于 smoke/repair。每个 mapping HTTP attempt 在发出前扣 1 个 weighted unit，retry 同样扣费；另有一次 audited User API preflight。 预算停止后返回可续跑 offset。分页完整但仍有 reconciliation backlog 时，状态可以是 partial_failed，但 next_offset 为 NULL。

该 API 不返回 identifier 生效日期，所以 valid_from/valid_to 保持 NULL，不能宣称 current-only 或 PIT。同一 instrument/type 的多个 validated values 作为 undated aliases 全部保留； 不能按 provider 返回顺序任取第一值。 MySQL 通过 generated valid_from_key 只在唯一约束内部把 NULL 归一化，业务字段本身不伪造日期。 外部 ID 只 enrich 已通过 provider symbol 严格定位的 instrument_id，不能反向触发 fuzzy merge。

6.4 Dividend And Split History

sequenceDiagram participant U as CLI/Menu/Python participant J as CorporateActionsHistoryJob participant E as EODHD div/splits participant P as parser/provider ingest participant DB as MySQL U->>J: symbols or canonical universe + hard budget J->>DB: deterministic instrument selection / resume checkpoint J->>E: User API allowance preflight loop bounded instrument batches J->>E: GET div and/or splits by provider_symbol E-->>P: provider payload P->>DB: short transaction: API audit + canonical upsert + DQ issues J->>DB: committed batch checkpoint end J-->>U: rows, failures, API units, resume cursor

src/fdp/get_data/corporate_actions/get_history.py owns universe selection、whole-task weighted budget、bounded parallel fetch、fatal stop、checkpoint 和 resume。HTTP calls occur outside database transactions。src/fdp/sources/eodhd/corporate_actions.py 显式映射 dividend/split payload； 无效的零/负现金值、无效 ratio 和同日冲突写入 quality issue，不做 silent coercion。 src/fdp/sources/eodhd/ingest/corporate_actions.py 在短事务内一起提交 API evidence、canonical rows 和 DQ issue，并串行化这些短写事务以避免并发 deadlock。

该 Job 的 universe 固定为 instrument.asset_type='stock'，CLI/Menu 没有 ETF/Fund selector。 每个历史事件先经过 CorporateActionIdentityResolver：事件日有效的 provider-symbol history 优先；没有 dated prior owner 时，唯一 current endpoint owner 可以保留 pre-rename history； dated non-stock owner 会被拒绝，重叠历史 owner 会进入 DQ。旧混合范围数据通过 j21 migrate corporate-action-identities 在备份后先迁移 dated stock rows，再删除所有剩余 non-stock corporate-action rows；该命令不改 ETF/Fund instrument 或 price tables。

2026-07-18 的真实收口与回填最终得到 867,857 条 stock corporate-action rows；非股票行、 natural-key duplicates 和 invalid typed rows 均为 0。任务 run 7030..7038 合计使用 99,800 API units；最终 inactive-stock run 7038 完成 23,846 个 instrument。解析器仍会 读取非股票 ticker owner 作为冲突排除证据，但 API 请求范围和 canonical 写入范围始终只含 stock。

初次历史回填使用 one-unit-per-symbol /div/{ticker} 和 /splits/{ticker}。Full-exchange date Bulk 每 action type/date 计 100 units，留给后续 daily incremental workflow。Menu 和 Typer 调用同一 Job；默认 dry-run，真实请求和写库必须显式确认。

7. Historical EOD 路径

j21 ingest history 根据 --asset-types 选择 stock、ETF、Fund、index Job 或通用 HistoricalDailyJob。--instrument-status active|inactive|all 控制 instrument master 匹配范围；旧 --include-inactive 仅为兼容参数。

flowchart TD A["history CLI/menu"] --> B["HistoricalDailyJob.preflight"] B --> C["resolve current/provider/history symbol"] C --> D["create aggregate ingestion_task_run"] D --> E{"for each resolved instrument"} E --> F["one DB transaction"] F --> G["load_historical_daily_price_unit"] G --> H["EodhdClient.get_historical_eod"] H --> I["record_api_call"] I --> J["parse_daily_price_rows"] J --> K["asset-specific upsert"] K --> E E --> L["finish aggregate task run"]

事务边界不是一个超大 transaction：parent task run 先提交，每个 provider symbol 独立 提交，最后再提交 aggregate counters。单 symbol 失败不会回滚之前已成功的 symbol； 401/402/403、数据库/parser exception 或连续全局 transient failures 会停止后续 work units。

IndexDailyJob 复用 historical base，但先确保 index instrument 存在，再写 index_daily_price。MarketCalendarJob 调用 exchange details/calendar parser，写入 market_calendar(calendar_date, is_trading_day, source)。

EODHD 历史 holiday payload 曾漏掉三个已证实休市日。US calendar parser 因此有显式、 有一手来源的 closure override：Nasdaq 2012 schedule 的 2012-01-02，以及 SEC/NYSE Arca 记录的 Sandy 2012-10-29/30。这些日期写 source NASDAQ_SEC_US_CLOSURE；不会从“返回行少”自动猜休市。

8. Bulk EOD 路径

8.1 单日 Bulk

j21 ingest daily
-> BulkDailyJob.run()
-> resolve explicit/latest ready New York trading date
-> delegate the one-date scope to DailyRangeJob
-> use the same task ledger, fetch/publish, reconcile, and validation contract

Stock/ETF 的 latest readiness 是纽约时间交易日 16:30；选择 Fund 时等待到下一日 06:30。 单日和多日不再维护两套写库逻辑。unmatched 不是垃圾，也不会被丢掉；它保留原始 payload、 vendor type、价格字段、首次/最近观察时间和分类状态，等待自动或人工后处理。

8.2 多日 Daily Range

j21 ingest daily-range --from ... --to ...
-> DailyRangeJob.preflight()
-> plan calendar/instrument prerequisites
-> build immutable task fingerprint and per-date fingerprints
-> estimate only unfinished provider work
-> dry-run by default; --execute --yes enters execution
-> exact completed task: return prior result with 0 provider calls
-> exact incomplete task: acquire stale/available lease and resume
-> overlapping task: reuse only verified dates
-> optional --new-run: create fresh task, unless live equivalent lease exists
-> refresh prerequisites + audited User API budget check
-> for each remaining date:
   claim work unit
   fetch outside DB transaction
   compare recent verified baseline; retry once when response is materially thin
   short transaction: published rows + pending rows + API audit + checkpoint
-> unless --manual: local classify -> route -> daily-price validate
-> mark verified dates and finalize task

--instrument-status active 适合每日增量；历史 backfill 使用 all。每次 HTTP attempt 在发出前 扣除真实 weighted units，retry 同样计费，预算不足时不发送请求。并发只改变“多个交易日同时 进行”，不改变短事务、upsert 唯一键或 audit 语义。长时间 provider/reconcile 阶段由后台 heartbeat 续租；同 scope 的 live lease 会拒绝第二个进程。出现 fatal 条件后取消尚未启动的 future，同时收集已经开始的 future，保证结果计数等于真实提交。

任务身份固定包含 source、market、exchange、日期范围、排序后的 asset types、local instrument status、symbol filter 和 data-contract version。workers、语言、输出格式、限速和 本次预算不是身份字段。held 表示响应偏薄或需要复核：有效数据可发布，但该日期不成为可 复用完成证据，后续同 scope 会再次尝试。逐日要求 source-row 闭合： fetched = published + pending + rejected；不闭合时该 work unit 保持失败/可续跑。

9. Bulk Unmatched Reconcile

flowchart TB Input["CLI / Guided Menu"] --> Job["BulkUnmatchedReconcileJob"] Raw["system.bulk_unmatched observation"] --> Summary["summary / list"] Job --> Summary Summary --> Classify["checkpointed classifier"] Classify --> Decision{"identity confidence"} Decision -- high or medium --> Matched["matched candidate"] Decision -- conflict or unsupported --> Hold["retained staging state"] Matched --> Preview["complete-group route dry-run"] Preview --> Confirm{"operator confirms?"} Confirm -- no --> Resume["preserve run checkpoint"] Confirm -- yes --> Route["atomic route batches"] Route --> Price["canonical daily price"] Route --> Audit["identity resolution audit"] Route --> Quality["quality run / issue"] Route --> Checkpoint["ingestion task checkpoint"] Price --> Validate["daily-price validation"]

操作顺序：

j21 reconcile bulk-unmatched summary/list
j21 reconcile bulk-unmatched classify
j21 reconcile bulk-unmatched status --run-id ...
j21 reconcile bulk-unmatched route --dry-run --run-id ...
j21 reconcile bulk-unmatched route --execute --yes --run-id ...
j21 validate daily-price

src/fdp/get_data/reconcile/bulk_unmatched.py 是统一 Job adapter；CLI 和 Menu 都调用 BulkUnmatchedReconcileJob。src/fdp/get_data/reconcile/workflow.py 负责创建、解析和保存 checkpoint_json；src/fdp/bulk_unmatched.py 负责 SELECT、身份决策和完整 natural-key group 路由；src/fdp/menu/reconcile_ui.py 只负责 Rich 展示，不拥有业务规则。

Classifier 默认每批 5,000 rows，用 (trade_date, observation_id) keyset cursor 读取固定 snapshot。MySQL 查询使用 (market, classification_status, trade_date, observation_id) 复合 索引。CLI 默认只处理 unresolved；Menu 默认处理 unresolved + needs_instrument + unknown。ambiguous 和 non_price_asset 必须显式使用高级 选项。整个 reconcile 路径不会构造 EODHD client，任务和 API log 验证值均为 0。

身份规则：有效日期内唯一 identifier history 是 high-confidence；没有历史冲突的唯一 current provider symbol 是 medium-confidence；无日期 CUSIP/ISIN/FIGI 只能辅助审计。多个 owner、历史 冲突或 EODHD type 不兼容都留在 staging，不猜测合并。

Router 每批最多处理 1,000 个完整 (instrument_id, trade_date) 组合。dated-history winner 优先，其余 alias 标为 shadowed。相同 provider symbol 可以刷新 EODHD row；不同 symbol 只有 新的 high-confidence 判定可以替换已明确记录为 medium-confidence 的 canonical identity。 同级、降级或旧 confidence 不明时禁止覆盖，保留原 row，并写 identity_route_conflict quality issue。route 时仍通过 parse_daily_price_rows() 校验 OHLCV， 并保留 source 当日 symbol/provider symbol。

一个 batch 内的 staging 更新、canonical upsert、identity audit、quality issue 和 checkpoint 共用一个 transaction。失败只回滚当前 batch，先前提交保留。Ctrl+C 后用同一 run_id 继续；scope 不一致会拒绝 resume。旧 research bulk-unmatched 和 ingest bulk-unmatched-route 在 v0.4 只是带 warning 的兼容代理，v0.5 删除。 每批及最终 validation 同时检查 observations_selected = routed + shadowed + route_failed 和 canonical writes = routed； 不闭合时不得报告 success。价格 payload 校验失败写 invalid_ohlcv 或 api_rejected_row， 不能误记为 identity conflict。

10. 质量、Repair 与 Quarantine

flowchart TD Price["canonical daily price + market calendar"] --> Validate["validate_daily_prices"] Validate --> Checks["duplicate / missing / OHLCV / calendar checks"] Checks --> Issue["system.data_quality_issue"] Issue --> Kind{"issue type"} Kind -- missing_trade_date --> Repair["repair plan -> confirm -> claim"] Repair --> API["EODHD backfill by instrument_id"] API --> Verify1["verify target row"] --> Resolve1["resolve issue"] Kind -- stored bad row --> Quarantine["quarantine plan -> confirm -> claim"] Quarantine --> Archive["archive payload/hash"] Archive --> Delete["delete locked source row"] Delete --> Verify2["revalidate"] --> Resolve2["resolve issue"] Kind -- asset_type_mismatch --> Reconcile["migrate daily-price-asset-types"] Reconcile --> Verify3["copy -> payload verify -> source delete"]

quality/checks/ 只生成 SELECT；quality/validation.py 负责写 check run 和 open issue。 质量检查不自动改市场数据。

instrument metadata 更正可能发生在旧价格写入之后。asset_type_mismatch 不走 quarantine； j21 migrate daily-price-asset-types --phase plan 只读列出 source/target/rows，execute 阶段按 chunk transaction copy 到当前 canonical type 表，完整 payload 验证通过后才删除 source。 同 natural key 的目标 payload 不一致时拒绝覆盖并回滚。

Repair 只处理缺失行：执行前重验 issue、instrument/provider symbol 和 plan status，从 confirmed 原子 claim 为 executing，按 instrument_id 回填；目标行存在后才 resolve。

Quarantine 处理已经存在的坏行：必须先归档 payload/hash，再删除锁定源行；归档数与删除数 不一致则失败。只有 exact duplicate payload 能自动 dedupe，冲突 payload 留给人工 review。

14. Intraday 1m validation path

flowchart LR Input["CLI / 双语Menu"] --> Job["EodhdIntradayValidationJob"] Job --> Client["EODHD /intraday"] Client --> Parse["严格1m parser + NY session"] Parse --> Temp["临时Parquet + checksum验证"] Temp --> File["repo外正式Parquet"] File --> Manifest["system.intraday_file_manifest"] Job --> Audit["ingestion_task_run + api_call_log"]

路径固定为 validation/source=eodhd/asset_type=stock/interval=1m/trade_date=YYYY-MM-DD/bucket=NN/part-<content-hash>.parquet。 一个文件只含一个 instrument/trade_date；自然键为 (source, instrument_id, timestamp_utc, interval)。时间戳存 UTC，交易日和 pre/core/after 用 New York 时区。MySQL 只保存 manifest，不保存 bars。

J21_INTRADAY_DATA_ROOT 必须是 repo 外绝对路径。缺失、相对路径、repo 内路径、根目录、 home 或 symlink 在创建 client/文件前失败。provider 请求最多覆盖 120 天，每次按 5 units， 公开验证命令含 /user 和 retries 的总 hard cap 为 200。测试只用 fixture/mock，真实调用为 0。
